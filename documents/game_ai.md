# AI: рекомендований шлях  
**Перший етап**  
Зробити повністю протестований генератор легальних ходів і простого випадкового AI. Це дозволить швидко перевірити правила, захоплення, відродження та крайові випадки.  
**Базовий конкурентний AI**  
Застосувати iterative deepening Minimax з alpha-beta pruning і лімітом часу, наприклад 300 мс для легкого рівня та 1–2 секунди для сильного.  
Оскільки є кубики, дерево має три типи вузлів:  
* Max: хід AI;  
* Min: хід суперника;  
* Chance: очікуваний результат наступного кидка 2d6.  
Замість 36 окремих результатів достатньо 21 унікальної комбінації кубиків із вагами ймовірності. Для різних значень кубиків потрібно перевіряти обидва порядки використання дій, оскільки захоплення після першої дії змінює другий хід.  
**Функція оцінки**  
Оцінювати позицію з погляду Клану Короля:  
```
+ дуже велике значення: Король стоїть на Виході
- дуже велике значення: Короля оточено трьома сторонами
+ кількість гвардійців
- кількість нападників
+ кількість відкритих шляхів Короля до Виходів
- кількість сторін оточення Короля
+ мобільність Короля й гвардії
- контроль нападниками сусідніх до Короля гексів
+ контроль Виходів гвардією
- безпосередні загрози захоплення гвардійців
+ можливість вигідного захоплення на поточному ході
```
Оцінка має враховувати, що Трон, Виходи та край дошки зараховуються як сторона оточення Короля лише за вашими правилами, а не автоматично переноситися з класичного Tablut.  
**Пізніший сильний AI**  
Після стабілізації правил можна перейти до MCTS із self-play. Це краще підходить для гри з кубиками та великою кількістю складених ходів. Нейромережа не потрібна для першої версії: хороший alpha-beta AI з правильною евристикою вже дасть сильного суперника.
