  
# Dwarf tafl — дизайн-документ PWA  
## 1. Призначення  
Офлайн-first браузерна тактична гра для мобільних, планшетів і desktop-браузерів.  
Основа — асиметрична tafl-подібна гра на полі з 61 гекса:  
* Клан Короля: 1 Король і 5 гвардійців.  
* Заколотники: 9 воїнів.  
* Мета Короля: дістатися одного з трьох Виходів.  
* Мета заколотників: оточити Короля трьома сторонами.  
* Кожен хід: кидок двох кубиків і виконання двох відповідних дій.  
Режими першої версії:  
1. Двоє гравців на одному пристрої.  
2. Один гравець проти локального computer AI.  
Позамережева гра, акаунти, онлайн-матчі, серверна синхронізація та рейтинги не входять до першої версії.  
## 2. Технічне рішення  
**Основний стек**  

| Зона              | Рішення                                       |
| ----------------- | --------------------------------------------- |
| Мова              | TypeScript                                    |
| Застосунок і UI   | React + Vite                                  |
| 2.5D ігрова сцена | PixiJS v8, WebGL2                             |
| 3D-кубики         | Three.js                                      |
| Фізика кубиків    | @dimforge/rapier3d-compat                     |
| Стан інтерфейсу   | Zustand                                       |
| Ігрові правила    | Чистий TypeScript без залежності від UI       |
| Локальне сховище  | IndexedDB через idb                           |
| Офлайн-робота     | PWA manifest + service worker + Cache Storage |
| AI                | Web Worker                                    |
  
PixiJS відповідає за поле, тайли, токени, підсвічування, частинки, шейдери, масштабування та події вводу. Three.js створює лише окрему 3D-сцену кубиків поверх гри. Це не перетворює всю гру на важку 3D-сцену.  
**PWA та локальні дані**  
* Всі графічні файли й код кешуються під час першого запуску.  
* Партії, налаштування, історія ходів, повтори та прогрес туторіалу зберігаються в IndexedDB.  
* Гра повинна запускатися й працювати без мережі після першого завантаження.  
* Після кожної завершеної дії стан партії автоматично зберігається.  
* Користувач може експортувати або імпортувати збереження у JSON-файлі.  
IndexedDB доречна для структурованих локальних даних PWA, а Service Worker кешує застосунок і статичні assets для офлайн-роботи. ++[web.dev: Offline data](https://web.dev/learn/pwa/offline-data)++, ++[web.dev: Service workers](https://web.dev/learn/pwa/service-workers)++

## 6. Взаємодія гравця  
**Початок ходу**  
1. UI показує активну сторону.  
2. Гравець натискає «Кинути кубики».  
3. Відтворюється 3D-анімація кидка двох кубиків.  
4. Після зупинки кубиків відображаються дві картки дій.  
5. Гравець вибирає одну доступну дію.  
6. Лише допустимі токени отримують підсвічування.  
7. Натискання на токен показує доступні гекси призначення та маршрут.  
8. Натискання на гекс виконує дію.  
9. Система перевіряє захоплення, анімує результат і переходить до другої дії.  
**Кубики та правдивість результату**  
Фізика кубиків є візуальним шаром, а не джерелом правил.  
1. Перед анімацією застосунок чесно обирає два результати через crypto.getRandomValues.  
2. Вони записуються в журнал подій.  
3. Three.js і Rapier відтворюють кидок, який завершується саме цими гранями.  
4. Після анімації застосунок показує результати як доступні дії.  
Це усуває нестабільність фізичного симулятора, але зберігає переконливий кидок.  
**Дії кубиків**  

| Грань    | Інтерфейс                                                        |
| -------- | ---------------------------------------------------------------- |
| 1–4      | Картка «Марш до N»                                               |
| 5 / Щит  | Вибір: один токен до 5 гексів або два різні токени на 1 гекс     |
| 6 / Руна | Вибір: необмежений рух по прямій або повернення втраченого воїна |
  
Після вибору картки дозволені лише токени та гекси, сумісні з обраною дією. Після першої дії допустимі ходи для другої дії обчислюються повторно.  
## 7. Анімації та шейдери  
**Гекси**  
* Обраний токен: м’яке золоте або холодне блакитне світіння.  
* Допустимий гекс: напівпрозора кольорова заливка.  
* Маршрут: тонка анімована лінія з напрямком.  
* Недоступний шлях: не підсвічується.  
* Вихід Короля: слабкий пульсуючий контур.  
* Трон: стримане світіння, лише коли важливий для правила.  
**Переміщення токена**  
* Тривалість: 180–360 мс залежно від кількості гексів.  
* Рух: плавний easeInOut, з ледь помітним вертикальним підйомом.  
* Токен зберігає читабельність і не обертається.  
* Камера не рухається під час звичайного ходу.  
**Захоплення**  
1. Ворожий токен коротко підсвічується темно-червоним.  
2. З’являється тонка тріщина або іскри металу.  
3. Токен зменшується, розчиняється й лишає 6–10 дрібних частинок.  
4. Токен прибирається зі сцени лише після завершення анімації.  
На мобільних пристроях застосовувати полегшений режим: без blur, менше частинок, максимум один активний shader filter.  
**3D-кубики**  
* Два beveled d6 із шістьма кастомними гранями.  
* Грані: 1, 2, 3, 4, Щит, Руна.  
* Тверда площина-лоток і чотири невидимі бортики.  
* Камера — коротка перспективна сценка поверх основного поля.  
* Симуляція: 60 fixed updates за секунду.  
* Після 1.5–2.5 секунди кубики м’яко фіксуються на запланованому результаті.  
* Результат дублюється у доступній текстовій картці дії.  
Rapier підтримує жорсткі тіла, колізії, JavaScript bindings та опційний детермінований режим. ++[Rapier](https://rapier.rs/docs/)++  
## 8. Computer AI  
AI запускається у Web Worker, щоб не блокувати анімації й торкання.  
**Рівні складності**  

| Рівень | Алгоритм | Орієнтовний час |
| -------- | ----------------------------------------------------------- | --------------- |
| Легкий | Випадковий вибір з базовим захистом від очевидних програшів | миттєво |
| Середній | Alpha-beta, 2–3 ply | до 250 мс |
| Важкий | Expectiminimax, iterative deepening | до 1.5 с |
  
**Функція оцінки**  
AI оцінює:  
* перемогу та поразку;  
* близькість Короля до Виходів;  
* відкриті маршрути Короля;  
* число граней оточення Короля;  
* контроль Виходів;  
* кількість живих гвардійців і нападників;  
* загрози захоплення;  
* мобільність фігур;  
* можливість повернення воїна Руною.  
Кубики створюють chance-вузли. Для другого й наступних ходів AI оцінює 21 унікальну комбінацію двох d6 з відповідними вагами ймовірності.

settings
  - audio, vibration, qualityMode, language, aiDifficulty

  - gameId, createdAt, updatedAt, mode, stateVersion, snapshot

events
  - gameId, turn, sequence, eventType, payload

replays

Збереження створюється після кожної ігрової події. Snapshot створюється кожні 10 подій для швидкого відновлення.  
## 11. Якість і тестування  
**Правила**  
* Unit-тести для кожного типу ходу.  
* Тести на захоплення біля Трону, Виходу та краю дошки.  
* Тести на оточення Короля.  
* Тести на Shield і Rune.  
* Тести на відновлення токенів.  
* Повтори партій мають відтворювати результат ідентично.  
**PWA**  
* Перший запуск онлайн.  
* Повний запуск в airplane mode.  
* Відновлення незавершеної партії після закриття застосунку.  
* Інсталяція на Android, iOS/iPadOS і desktop Chrome/Edge/Safari.  
* Перевірка touch, keyboard і mouse.  
**Продуктивність**  
* 60 FPS на сучасних пристроях.  
* Не нижче 30 FPS на бюджетному mobile.  
* Не більше двох активних shader effects одночасно.  
* AI не блокує головний UI thread.  
* Режим Reduced Motion вимикає частинки та скорочує анімації.
